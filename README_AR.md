# خريطة أجهزة البصمة — النسخة الآمنة العامة

هذه النسخة تحوّل الموقع القديم الثابت إلى تطبيق عام يعمل عبر HTTPS من هاتف أي موظف. واجهة الموظف عامة، أما الإدارة فتعمل بحسابات وصلاحيات حقيقية على الخادم.

## ما تغيّر

- إضافة وتعديل وحذف الأجهزة مباشرة من لوحة الإدارة.
- تخزين الأجهزة في قاعدة البيانات وإظهارها فورًا لجميع الهواتف.
- إبقاء `/devices.json` كرابط ديناميكي متوافق مع النسخة القديمة.
- حسابات إدارية بثلاث صلاحيات: مدير عام، مسؤول أجهزة، مشاهدة فقط.
- تشفير كلمات المرور باستخدام Argon2؛ لا توجد كلمة مرور داخل HTML أو JavaScript.
- جلسات دخول مخزنة في الخادم مع Cookies آمنة وHttpOnly.
- حماية CSRF، إيقاف محاولات الدخول المتكررة، وسجل تدقيق للعمليات.
- إجبار كل مستخدم جديد على تغيير كلمة المرور عند أول دخول.
- استخدام خريطة OpenStreetMap الخفيفة مباشرةً من دون حساب أو مفتاح API أو فوترة، ومن دون الحاجة إلى WebGL.

## التشغيل التجريبي على Windows

1. انسخ `.env.example` باسم `.env`.
2. غيّر `BOOTSTRAP_ADMIN_USERNAME` و`BOOTSTRAP_ADMIN_PASSWORD` إلى بيانات المدير الأول. يجب أن تحتوي كلمة المرور 10 محارف على الأقل وحرفًا ورقمًا.
3. شغّل `start_local.bat`.
4. افتح `http://127.0.0.1:8000`، ولوحة الإدارة في `http://127.0.0.1:8000/admin`.

التشغيل المحلي للاختبار فقط. زر GPS على هاتف الموظف يحتاج رابط HTTPS عام.

## النشر العام

يجب نشر الحزمة على خدمة تستضيف تطبيق Docker أو Python وتمنح رابط HTTPS عامًا. GitHub Pages وحده لا يستطيع تشغيل الخادم أو قاعدة البيانات.

### المسار الموصى به للمستودع الحالي

1. لا تعدّل فرع `main` في البداية حتى تبقى نسخة GitHub Pages القديمة عاملة.
2. أنشئ فرعًا جديدًا باسم `server-v2`.
3. ارفع **محتويات مجلد المشروع** إلى جذر الفرع الجديد؛ يجب أن يظهر `app.py` و`render.yaml` في المستوى الأول، وليس داخل مجلد إضافي.
4. اربط Render بالمستودع واختر Blueprint أو Web Service والفرع `server-v2`.
5. ملف `render.yaml` يحدد منطقة Frankfurt ومهيأ لخطة Render المجانية بغرض الاختبار. قبل الاستخدام الفعلي للموظفين، غيّر Web Service إلى خطة لا تتوقف عند الخمول.

لا تستخدم SQLite في Render المجاني لأن نظام الملفات مؤقت. استخدم رابط PostgreSQL دائمًا في `DATABASE_URL`.

إعدادات البيئة المطلوبة في الاستضافة:

```text
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE
BOOTSTRAP_ADMIN_USERNAME=admin
BOOTSTRAP_ADMIN_DISPLAY_NAME=المدير العام
BOOTSTRAP_ADMIN_PASSWORD=ONE_TIME_STRONG_PASSWORD
SESSION_HOURS=12
COOKIE_SECURE=1
```

للنشر العام يوصى بـ PostgreSQL. إذا استُخدمت SQLite، فيجب ربط مجلد `data` بقرص دائم؛ وإلا قد تضيع البيانات عند إعادة تشغيل منصة الاستضافة.

أمر التشغيل العام:

```text
uvicorn app:app --host 0.0.0.0 --port $PORT --proxy-headers
```

بعد أول دخول، سيجبر النظام المدير على تغيير كلمة المرور. بعد إنشاء المدير في قاعدة البيانات يمكن حذف متغير `BOOTSTRAP_ADMIN_PASSWORD` من إعدادات الاستضافة؛ لن يعيد النظام إنشاء الحساب ما دامت قاعدة البيانات تحتوي مستخدمين.

## الصلاحيات

| الدور | الأجهزة | المستخدمون | سجل العمليات |
|---|---:|---:|---:|
| مدير عام | إضافة وتعديل وحذف | إدارة كاملة | مشاهدة |
| مسؤول أجهزة | إضافة وتعديل وحذف | لا | لا |
| مشاهدة فقط | مشاهدة | لا | لا |

واجهة الموظف لا تحتاج حسابًا. يفتح الموظف الرابط أو QR، يسمح للموقع باستخدام GPS، ثم يرى أقرب جهاز.

## ملاحظات أمنية مهمة

- لا ترفع ملف `.env` إلى GitHub.
- لا تحتاج OpenStreetMap إلى مفتاح API أو حساب فوترة لهذا الاستخدام التفاعلي الخفيف، مع وجوب إبقاء نسبة الخريطة ظاهرة وعدم تنزيل الخرائط للاستخدام دون اتصال.
- أبقِ `COOKIE_SECURE=1` في الموقع العام.
- استخدم HTTPS فقط، وخذ نسخة احتياطية دورية من PostgreSQL.
- لا تجعل قاعدة البيانات متاحة مباشرة للإنترنت؛ التطبيق وحده يتصل بها.
- أنشئ مديرًا عامًا احتياطيًا بعد أول دخول.

## إنشاء QR

بعد الحصول على الرابط النهائي، يكون QR للرابط العام للواجهة الرئيسية، مثل:

```text
https://example.com/
```

لا تستخدم رابط `/admin` داخل QR المخصص للموظفين.

## الاختبار الآلي

بعد تثبيت `requirements-dev.txt` شغّل:

```text
python tests/smoke_test.py
```

يفحص الاختبار: تسجيل الدخول، تغيير كلمة المرور الإجباري، الصلاحيات، إضافة جهاز وتعديله، التحديث الفوري لـ `/devices.json`، سجل العمليات، وتسجيل الخروج.
